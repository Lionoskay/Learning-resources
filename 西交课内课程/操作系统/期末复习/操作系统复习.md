# 操作系统复习

## ====章一：导论====

### 1.1操作系统的定义与特征

#### 1.1.1定义

操作系统是管理和控制计算机系统中软硬件资源，合理组织计算机工作流程，方便用户操作使用机器的程序的集合

#### 1.1.2特征

##### 1.1.2.1执行的并发性

计算机中存在多个并发运行的程序

##### 1.1.2.2资源的共享性

计算机中的多个系统资源可以由内存上的多个进程同时共享

##### 1.1.2.3操作的异步性

多个进程的执行顺序不是一贯到底的按照顺序执行，而是以不可预测的方式走走停停

##### 1.1.2.4虚拟性

通过将物理实体映射为若干个虚拟的逻辑实体（虚拟处理器，虚拟存储器，虚拟I/O设备）



### 1.2操作系统的功能

- 进程管理——process management
- 内存管理——memory management
- 设备管理——device management
- 文件系统管理——flie management
- 用户接口与作业管理

### 1.3三种基本的操作系统类型和特征

#### 1.3.1批处理系统——Batch processing system

- 作业/进程/任务成批的送入计算机中处理
- 不具有**交互性**，适用于大规模计算任务，减少交互带来的额外性能开销
- **多道程序运行**，several processes run in the memory at the same times
- 脱机操作

- ==**<u>*运行效率是核心*</u>**==



#### 1.3.2分时系统——Time Sharing

- 具有**强交互性**，保障人与计算机的交互
- **同时性**，适用于多个用户同时使用一台计算机时，公平的保证每一个用户能同时的进行交互
- 独立性，多个用户的进程和资源相互独立

- 及时性，**能及时的对用户的请求产生反应**

- ==<u>***交互性是核心***</u>==



#### 1.3.3实时系统——Real time

一种特殊的分时操作系统，分为**硬实时系统**（hard real time）和**软实时系统**（soft real time）

- 硬实时系统**强制保证每一个进程都能在截止时间前完成**
- 软实时系统通过**优先级**的方式，给目标进程高优先级保障其先行完成

**特点**：

- 及时性：能**及时的**反应请求，且**及时性强于分时系统**
- 具有实时的时钟管理，保障**进程在deadline前完成**

- 安全性高，但是资源利用率低

- <u>***==实时性是核心==***</u>



### 1.4多道程序运行与特点

#### 1.4.1定义

多道程序设计——multiprogramming，允许多作业同时进入内存中轮流交替占用CPU运行的技术

Several processes are running in a **interleaved** manner on the memroy

#### 1.4.2特点

- 多道性——多道程序同时**加载到内存上**，实现多道程序同时运行
- 宏观上并行
- 微观上串行

### 1.6操作系统的运行模式

An operating system is usually run in Dual-mode, which allows the OS to protect itself an other system components

#### 1.6.1User mode——用户态（目态）

操作系统中的用户态进程只能执行**普通指令 normal instructions**，特权低，只能访问特定的存储区域

#### 1.6.2Kernal mode——内核态（管态）

- 操作系统中的**内核态进程 kernal mode process** can execute **all instructions**, including normal instructions and **privileged instructions** 内核态进程可以执行所有指令（特权指令和普通指令）

- 特权指令——privileged instruction：只能在操作系统的内核态执行的指令





#### 1.6.3管态和目态间的切换

通过系统调用 system call 的方式切换，在用户态进程中**发起system call**，将trap信号传递进内核态，**通过内核判断是否执行system call**完成切换

中断

### 3.2<u>*进程的状态转换*</u> ==重点==

#### 3.2.1Process scheduling queues: 进程调度队列

- **Job que**: set of **all processes** in the system
  - When a process is created, it will be placed in the Job que.
  - When a process is in Job que, it may not be in memory. 当进程处于任务队列中时，可能不在内存中，需要通过中级调度从外存调度进内存
- **Ready que**: set of all processes **waiting in memory**, ready and waiting to execute.
  - When a process is in Ready que, it must be in memory. 当进程在ready que中，一定处于内存中，对应状态转换中的Ready态
- **Device ques**: set of processes waiting for I/O devices
  - **是多条队列的集合**，可以认为状态转换中的**Block**态就是处于Device ques中等待

#### 3.2.2**<u>*三种调度方式*</u>** ==重点==

- **Long-term scheduler**(Job scheduler): select the process in the **Job que** and brought it into **ready que**，**然后创建进程**
- **Mid-term scheduler**: 将内存中的不需要的进程挂起到外存中suspend
- **Short-term**: choose process form **ready que** to execute in CPU.从任务队列中选一个进程放入CPU中执行

#### 3.4.2消息传递 message passing

进程间的通信经过内核统一处理分发

![image-20251224234418456](C:\Users\30606\AppData\Roaming\Typora\typora-user-images\image-20251224234418456.png)

进程间的消息传递通过建立两个进程之间的通信链路实现信息的交换，依赖下面两个系统调用

- Send()  发送方将数据发送给内核缓冲区
- receive()   接收方从内核中读取数据

两种方法实现两个进程间消息的传递，要经过**内核**的管理

- 直接通信 direct communication

  - 要**直接指定通信的进程双方**
  - 要**明确知晓通信双方的身份**
  - - send() 和 receive()要直接指定对应的进程
    - **两个进程之间只能有一个通信通道**

- 间接通信 indirect communication

  - 通过邮箱的形式，**内核维护多个mailbox**，a mailbox可以对应多个进程，**相当于在内核维护的共享存储**

  - 不需要知道发送和接收双方的身份

## ====章四：线程====

### 4.1线程的概念——操作系统中接受CPU调度的最小单位

**<u>*Threads are the unit of scheduling, threads are basic units of CPU utilization*</u>**

- 在操作系统中，**进程**是操作系统的**资源分配的最小单位**，独立持有**操作系统的资源**

- 线程是操作系统中**接受CPU调度的最小单位**，在就绪队列中接受CPU调度时通过**调度线程进入CPU中执行**，而不是将进程调入到CPU中执行

- 线程是“轻量化”的进程
- 线程是**指令执行**的最小单元

#### 5.3.1 几种调度算法和区别

![image-20251227173720463](C:\Users\30606\AppData\Roaming\Typora\typora-user-images\image-20251227173720463.png)

- **短作业优先SJF**是根据**运行前估计的总运行时间最短**进行调度，不是运行到某一时刻的剩余时间最短
- **优先级调度**中，为了避免**饥饿**，采用**老化**或者**优先级提升**的方法

##### 5.3.1.1 多级队列调度

- **多级队列调度中**，某个进程一旦被分配到某个队列，**将无法进入另一队列，除非进程终止**。
- 通过给每一级队列分配优先级等方式决定**队列间的调度算法**，一次从多级队列中**调度出一个进程**进行执行。高优先级队列中的进程永远可以优先执行
- 多级队列中，每一级队列之间按照**作业属性**进行划分，具有不同作业属性的作业分配到不同的作业队列中且保持不动
- 每一级队列的调度算法都可以不同

##### 5.3.1.2 **多级反馈队列**

- 进程可以**动态调整的分配**在不同的优先级的队列中，若某一进程运行时间过长，可能会被分配到低优先级的队列，让其暂缓执行。
- 多级反馈队列**使用时间片大小进行队列划分**，时间片越小的进程优先级越高
- 大部分队列采用时间片轮转的方式，少部分队列采用FCFS

### <font color='red'>6.1. 临界资源与临界区</font>

> :one:临界资源：只能同时给一个进程使用的资源，比如打印机
>
> :two:临界区：<font color='red'>进程中访问**临界资源**的一段代码</font>，每进程都有一段临界区代码(可不同)，在该区中进程可修改共享变量等，一个进程在其临界区时，同类进程都不可以进入临界区
>
> :three:访问临界资源的过程：
>
> 1. 进入区：检查**可否进入**临界区的一段代码，若可以则设置相应“正在访问临界区”标志
> 2. 临界区：
> 3. 退出区：属于临界区，清除“正在访问临界区”标志
> 4. 剩余区：代码其余部分
>
> :four:进程对临界区互斥访问的实现
>
> 1. 空闲则入：临界区无进程时，进程请求加入临界区就进吧
> 2. 忙则等待：临界区有进程了，禁止其他请求进入临界区的请求
> 3. **有限等待：进程请求访问临界资源后，就应该在有限时间内加入临界区，不死等**
> 4. 让权等待：一个进程不能进入自己的临界区时，释放处理器阻塞自己

### 6.5 管程 monitor

<img src="https://s2.loli.net/2023/11/06/IXcmYpQklBH2CLg.png" alt="image-20231106214404038" style="zoom: 67%;" /> 

:one:定义：关于共享资源的数据结构及一组针对该资源的操作过程所构成的软件模块

:two:基本思想：把信号量+操作原语(共享变量+对共享变量的操作)封装在一个对象内部

:three:功能：集中管理进程中互斥访问的临界区，保证进程对于共享资源的互斥访问

:four:特点：局部于管程的数据只能被管程内部访问，进程只有通过调用进入管程才能访问共享数据，每次只允许一个进程调用管程

:five:管程的同步设施

1. 条件变量：仅能从管程内进行访问，用于表示进程不同的等待原因
2. wait和signal函数：进程调用wait后会被阻塞然后释放管程，调用signal唤醒在该条件变量上阻塞的进程

#### 7.2.3 死锁检测

- 先分配后检测，在资源分配后再检测当前系统中是否存在死锁
- 与银行家算法的区别是：
- - 银行家算法再每次请求到来后都需要检测当前请求是否合法
  - 仅当当前请求合法才能分配
- 死锁检测算法：
- - 资源分配后定时检查
  - 不需要维护MAX
  - 通过在当前所处的状态下检测是否有死锁产生实现
  - - 若**有死锁产生**，进入死锁解决（**死锁恢复**）中

![image-20251227220735111](C:\Users\30606\AppData\Roaming\Typora\typora-user-images\image-20251227220735111.png)

- 通过检测当前状态下每个进程能否执行检测死锁，若不存在每个进程都能执行的顺序，则有死锁
