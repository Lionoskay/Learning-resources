- 若访问快表TLB：首先从快表中获取页面在内存中的地址，然后进入内存中访问对应的地址

$$
页面访问用时=访问快表时间+内存访问时间
$$

- 若访问主存：首先访问快表，没找到对应的页面再去访问主存中的页表，根据当前的n级页表结构，每次访问一次页表就要访问一次主存

$$
页面访问用时=访问快表用时+访问主存用时*(当前访问第n级页表+1)
$$

当前访问第一级页表得到实际物理地址后，需要再访问一次主存才能访问到实际页面

- 若都不在，**触发缺页中断**，需要访问外存，从外存中拉入到内存后**再次访问内存**

$$
\textbf{页面访问用时=访问快表用时+访问内存中页表用时(缺页)+换出swap out+换入swap in用时等}
$$



# 内外碎片

- External fragmentation——Free gaps bewteen allocated chunks
- internal fragmentation——don't need all memory within allocated chunks

## 固定分区——Fixed partition

- 分区大小固定，每个分区内只分配一个进程，存在**内碎片**
- **无外碎片**：分区预先连续分配，分配后不产生分散的外碎片空闲块
- 优点是实现方式简单，缺点是分区大小固定，内存利用率低，内碎片浪费严重

## 可变分区——Dynamic partition

- 分区大小与进程实际需求匹配，**无内碎片**，每个分区大小与需要进到内存中的进程的大小一致，不分页，整体拉入内存
- 内存多次释放与回收后，**存在外碎片**
- 优点是内存利用率高，每个分区大小与进程实际所需大小完全相同
- 缺点是实现复杂，需要通过**内存紧缩**技术消除外碎片，且实现算法（**首次适应First-fit, best-fit等实现困难**）
- 内存紧缩技术：**Compaction**

## 段式——Segmentation

- 无**内碎片**，段的大小与进程的某一段（代码段/数据段）大小一致，是动态分配的可变大小区域
- 有**外碎片**，多次分配释放后存在不同大小的不可利用的空闲块
- 优点是按照逻辑分段，便于段的共享和保护
- 缺点是外碎片，段长有差异
- 需要维护一个段表 segment table，存放程序逻辑段映射到内存上的物理段的位置

- 段表中需要包含：
- - Base基址，段在内存中的起始地址
  - limit段的长度
- 引入两个段表寄存器：STBR和STLR：
- - STBR：Segment-table base register
  - STLR：Segment-table length register

## 页式——Paging

- 有**内碎片**：分页式按照**设定好的页大小**分割程序的**逻辑地址空间**，然后分配到内存上同样大小的块/帧 frame上，若某进程大小不是页的整数倍，会留下内碎片
- 无**外碎片**：分页式**页面大小固定**，即使释放后也可以重新分配相同大小的页面，不存在空闲块无法分配问题
- 优点是内存利用率高，无外碎片，内存分配/回收简单
- 缺点是按照逻辑分页，逻辑上连续的页物理上不一定连续，存在内碎片

## 段页式——Segmentation paging

- 段页式的逻辑是：
- - **逻辑地址上分段**：程序逻辑地址上按照代码段/数据段的大小分段
  - **逻辑地址的段内分页**：在每个段内按照固定大小进行分页
  - **物理地址分页**：在物理地址上**不分段，只分页**，通过页框存放每个页
- 需要维护**系统级的段表**：整个系统层面上维护一个段表，找到对应的**段内页表地址**（从逻辑地址映射到虚拟地址）
- **维护段内页表**：为每一个段维护一个页表，查询时首先根据**段号**找到**段内页表**的位置（一次内存访问），然后再访问段内页表找到**页面在物理内存上的地址**（两次内存访问），然后再访问物理内存上的页面地址
- 优点是按照逻辑分段，便于程序的维护
- 缺点是**存在内碎片**（物理内存上实际采用页），硬件开销大

  > > >
  > > > **只能顺序访问**——批量读取效率高，随机读取效率低，需要顺序的遍历每一个文件才能到达目标文件

  > > > ![image-20251228142955394](C:\Users\30606\AppData\Roaming\Typora\typora-user-images\image-20251228142955394.png)

  > > > 2.**索引文件**——Index file
  > > >
  > > > **支持随机访问**——使用索引表记录该文件中**每一个记录项**的地址

  > > > ![image-20251228143023049](C:\Users\30606\AppData\Roaming\Typora\typora-user-images\image-20251228143023049.png)

  > > > **3.索引顺序文件**——Indexed Sequential file
  > > >
  > > > **兼顾随机访问和顺序访问**，先索引找到目标块，然后顺序访问

## 如何实现文件的共享

### Hard link 硬链接——文件别名实现法

- 文件目录中的目录项定义了**文件名**到**文件地址信息（Inode）**的映射关系：

![image-20251228150323510](C:\Users\30606\AppData\Roaming\Typora\typora-user-images\image-20251228150323510.png)

- 要实现共享，硬链接思路为：
- **通过多个文件名链接同一个iNode索引节点**实现文件多个**平等的别名**
- 要**记录文件别名的数目**，删除文件时**当文件的所有别名都删除**后才将文件删除
- **限制在于**：**链接一个新的别名时，该文件必须与要链接的文件处于同一个文件系统中**（很好理解，都具有相同的根目录才能完成这个子节点的映射）

### 连续分配

![image-20251228160451942](C:\Users\30606\AppData\Roaming\Typora\typora-user-images\image-20251228160451942.png)

![image-20251228160504337](C:\Users\30606\AppData\Roaming\Typora\typora-user-images\image-20251228160504337.png)

![image-20251228160526945](C:\Users\30606\AppData\Roaming\Typora\typora-user-images\image-20251228160526945.png)

- 连续分配时，在FCB中通过**某个文件的第一块的块号+块长度**记录**每个文件的地址**
- 外存中的**块号**是**按顺序排列的**，找到文件的块号就是找到了文件的首地址
- 要支持随机存取，即**可以定位到每个物理块上**，完成对特定物理块的访问
- 随机存取时只需要获得块号（首地址）+块偏移就能找到特定物理块的地址

![image-20251228160601679](C:\Users\30606\AppData\Roaming\Typora\typora-user-images\image-20251228160601679.png)

- **支持顺序存取和随机存取**，因为FCB中记录了**每一个块的起始地址**
- 但是文件不能动态增长，需要提前预留空间（提前声明了文件长度，分配了这段空间）
- 在磁盘中**存在外碎片问题**

### 链接分配

![image-20251228160832143](C:\Users\30606\AppData\Roaming\Typora\typora-user-images\image-20251228160832143.png)

- FCB中**记录文件的起始块号和结束块号**，内部块的链接关系不可知
- 寻道次数慢，想访问某个**目标块**时需要**从头结点开始遍历**
- 不适于随机存取，内部块的链接关系不可知，**特定物理块**的访问必须依赖头结点指针
- 支持动态增长，只需要找到空闲物理块然后分配指针即可
